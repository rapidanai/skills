# Audience modes and quality evaluation plan

Scope: preserve the four analysis lenses, add Developer / Plain language / Learning presentation, built-in question explanations, before/after code token estimates, and distributable evaluation scenarios.

1. Establish baseline gaps with the current skill and a small source fixture.
2. Add shared mode and code-token comparison contracts; adapt questions, reports, and plans. Keep evidence and analysis depth identical across modes, and preserve report/plan/implementation boundaries.
3. Correct overbroad SOLID heuristics and uncertain-orphan handling. Add confidence, practical consequences, coverage, and behavior-based verification guidance.
4. Bundle fixtures, scenario prompts, an explicit scoring rubric, and a validation script. Use independent agents to exercise the revised guidance; report simulations separately from live host testing.
5. Validate the complete installable package and installer suite, then publish the update.

Critical checks: plain language preserves evidence and risk; Learning does not imply deeper audit; explaining a question does not answer it or authorize edits; unsupported savings remain unknown; dynamic plugins and simple direct imports do not produce false positives; limited coverage is not presented as a clean bill of health.
