# The review loop

The rhythm of this skill is one section at a time, with the user in the loop on every change. This file is the detailed protocol; SKILL.md is the summary.

## Present one section

Show the current text of exactly one section, verbatim. Format it so it reads cleanly in chat: quote the headline, body, and any transition line as separate lines. Do not paraphrase, summarize, or silently fix typos — the user needs to see what is actually there.

Do not include the next section. Do not preview your proposed changes.

## Let the user speak first

After presenting, stop. Ask nothing leading. The user gives line-level feedback; your job is to receive it. Do not offer a rewrite before they have told you what is wrong. If they ask "what do you think?", give a short, honest read and then hand it back.

## Apply corrections exactly

When the user gives feedback, apply it precisely — their words, their phrasing. Then show the revised section in full so they can see the result. If a correction is ambiguous, ask one clarifying question rather than guessing.

If the user says "rewrite it" without specifics, produce a revision in their voice (guided by the profile) and present it as a proposal, not a fait accompli.

## Sign-off gates advancement

Only move to the next section when the user approves the current one. Approval sounds like "good", "that works", "ship it", "yes". Silence is not approval. If they raise a new point, stay on the section.

## When the user wants the whole piece at once

If the user wants to review the whole page in one pass instead of section by section, follow their lead — but still apply edits one change at a time and still capture lessons. The section-by-section default keeps the loop tight; it does not override the user.

## End the session

When the user stops or the page is done:

- List the sections edited.
- List the lessons captured, one line each.
- State the profile path.
- Offer next steps: another page, or applying the profile to new copy.
